# AGENTS.md

This file provides guidance to AI coding agents working in this repository.

## Overview

Personal configuration for the terminal environment the user runs AI coding agents in. There is no application code — the deliverables are per-tool config files plus the shell scripts that install them. `CLAUDE.md` is just a pointer to this file.

Each tool lives in its own top-level folder with its own `install.sh`. The root `install.sh` only dispatches to those: it runs `<tool>/install.sh` for each tool named on the command line (default: `ghostty herdr`), and when run via `curl` with no checkout it first downloads the repo tarball into a temp dir. A new tool gets a folder with an `install.sh`; add it to `DEFAULT_TOOLS` in the root script only if it should install by default.

The everyday look is light on every tool. `themes/herdr-ink/` is an optional dark bundle; never change the default configs to match it.

## Commands

```sh
./install.sh [tool...]      # install from this checkout (default: all default tools)
```

## Per-tool guidance

Each tool folder has its own `AGENTS.md` (with a `CLAUDE.md` pointer) covering its commands, install target, and config conventions. Read it before editing that folder:

- `ghostty/AGENTS.md`
- `herdr/AGENTS.md`

When adding a tool folder, give it the same pair.

## claude/, codex/

Placeholders; the user will add these configs themselves. Never commit credentials or account state (`~/.claude.json`, `~/.codex/auth.json`).

## themes/herdr-ink/

A manually applied dark theme bundle (Ghostty + Herdr + Claude Code) matching the herdr.dev site palette. No install script touches it. Read `themes/herdr-ink/README.md` before reading, editing, or applying it.

## Commit messages

Keep commit messages plain. **Do not add `Co-Authored-By` trailers or any other "generated by AI / co-authored with an assistant" attribution.**

## Writing markdown

When writing or editing any markdown file (plan docs, this file, etc.), do not hard-wrap paragraphs or insert arbitrary line breaks to keep lines short. Ignore line-length limits entirely — let each paragraph be a single long line and rely on the editor's soft wrap. Only break lines where a break is semantically meaningful (separate paragraphs, list items, headings).
